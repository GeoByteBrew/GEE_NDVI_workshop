The big picture: what are we doing?

The question is simple: how healthy is the vegetation in three forested counties of the north-eastern United States, and how did it change during the summers from 2014 to 2025?

To answer it, we take 12 years of Landsat 8 images, remove the clouds, compute a "greenness score" (NDVI) for every pixel, and turn those scores into maps, classes and charts. The whole script follows these eight steps:

How does GEE work? Your code is like a recipe. You send the recipe to Google's servers; they hold the ingredients (petabytes of imagery) and do the cooking. They also only cook the part you are looking at on screen. That is why working with 12 years of data takes seconds, while an Export computes the whole area and can take minutes.
Core concept

A satellite image is really a table of numbers

Think of a phone photo: it is made of small squares called pixels. In Landsat, each pixel covers 30 × 30 metres on the ground, so a football pitch is roughly 8 pixels.

The difference: a phone measures 3 colours per pixel (red, green, blue). Landsat also measures kinds of light our eyes cannot see. Each kind of light is a separate layer called a band. An image is a stack of band layers.

The bands used in the workshop:

Band name (in code)LightWavelengthUsed for

SR stands for "Surface Reflectance": values corrected for atmospheric effects, close to the true reflectance of the ground.

FeatureCollection: shapes with an attribute table

TIGER/2018/Counties is a ready-made dataset with the boundaries of every US county. Each county is a Feature: a shape plus a row of attributes (name, state code…). Together they form a FeatureCollection, the GEE equivalent of a vector layer in QGIS.

Step 2 · script section 2

ImageCollection: a stack of images taken over time

Since 2013, Landsat 8 has passed over every point on Earth every 16 days and taken a picture. Each pass produces one image covering a strip of land (a "scene" of about 185 × 180 km). All of them sit in the LANDSAT/LC08/C02/T1_L2 collection: hundreds of thousands of images worldwide.

Two filters shrink it down to a small stack we can use:

var landsat = ee.ImageCollection('LANDSAT/LC08/C02/T1_L2')
  .filterDate('2014-01-01', '2026-01-01')  // end date is excluded → up to the end of 2025
  .filterBounds(forests)                   // only scenes touching our counties
  .map(prepL8);                            // apply the preparation function to each one

print('Number of Landsat images', landsat.size());
In this version: the end date is '2026-01-01' so all of 2025 is included (GEE excludes the end date). The composite is built from the spatially filtered collection, not from a worldwide unfiltered stack.
Concept

.map(): applying the same operation to every image

The stack holds hundreds of images and we want to do the same thing to each of them: remove clouds, rescale the values, compute NDVI. So we write the operation once as a function, then apply it to every image with .map().

Analogy: a photo-editing macro that applies the same filter to every picture in an album. The function describes what to do with one photo; .map() runs that recipe on the whole album. 400 images in, 400 images out.
Step 3 · function prepL8

Cloud mask: reading the QA_PIXEL band

A cloud hides the forest underneath. The NDVI of a cloudy pixel measures the cloud, not the forest, so we have to drop those pixels.

Landsat gives each pixel a quality flag: the QA_PIXEL band. It is a single number, but it actually packs 16 yes/no answers. Written in binary, each digit (bit) answers one question:

BitQuestionBitQuestion
0Fill (no data)?5Snow?
1Dilated cloud?6Clear?
2Cirrus?7Water?
3Cloud?8–15Confidence levels (two bits each)
4Cloud shadow?

1 << 3 means "shift 1 three places to the left": 1000 in binary, which is 8. 1 << 4 = 16. bitwiseAnd(8) looks only at bit 3: if the result is 0, the bit is off and the pixel is not a cloud.

function prepL8(image) {
  var qa = image.select('QA_PIXEL');
  var mask = qa.bitwiseAnd(1 << 3).eq(0)       // cloud bit off AND
    .and(qa.bitwiseAnd(1 << 4).eq(0));          // shadow bit off → 1 (keep), otherwise 0
  var sr = image.select('SR_B.').multiply(0.0000275).add(-0.2);  // scaling (see below)
  return image.addBands(sr, null, true).updateMask(mask);
}

updateMask treats pixels where the mask is 0 as "missing". They are not deleted, but no later calculation uses them, and they show as transparent on the map.

Step 5 · script section 3

NDVI: a "health score" for vegetation

A healthy leaf does two things at once:

It absorbs red light. Chlorophyll uses red light for photosynthesis, so the leaf reflects very little red.
It strongly reflects near infrared (NIR). The leaf's internal cell structure bounces NIR back like a mirror. We cannot see it, but the satellite can.

Soil and water do not show this pair. The bigger the gap between the two, the denser and healthier the vegetation.

NDVI turns that gap into a single number:

NDVI = (NIR − Red) / (NIR + Red)

Why divide? The same forest looks brighter on a sunlit slope and darker on a shaded one, but the ratio stays the same. The result is always between −1 and +1.

function addNDVI(image) {
  // normalizedDifference(['A','B']) = (A − B) / (A + B)
  var nd = image.normalizedDifference(['SR_B5', 'SR_B4']).rename('NDVI');
  return image.addBands(nd).select('NDVI');
}
var ndvi = landsat.map(addNDVI);   // one NDVI image per image in the stack

normalizedDifference is the built-in shorthand for nir.subtract(red).divide(nir.add(red)). The result is identical.

Step 4 · the most important methodological point

Scale factor: turning raw numbers into real reflectance

Above we used reflectance values like 0.04 or 0.45. Landsat files do not store them that way. To save space they are converted to integers: instead of 0.45 the file says 23,636. These are called DN (Digital Numbers).

The USGS formula to convert them back:

reflectance = DN × 0.0000275 − 0.2

If you skip this conversion and compute NDVI on the raw numbers, you might think "it's a ratio, so it doesn't matter" — but the −0.2 offset breaks the ratio. The value computed from raw numbers actually equals:

unscaled NDVI = (NIR − Red) / (NIR + Red + 0.4)

The extra 0.4 in the denominator makes every NDVI value too small and squeezes them together. The comparison below updates as you move the sliders above:

Step 6

Composite: reducing 400 images to one

To show a single picture on the map, or to clip an area (clip), we need one image. We get it by summarising each pixel's values over time into a single value. This is called a composite.

Say we measured one pixel on 9 dates. The mask removed most clouds, but on two dates a cloud edge or haze slipped through:

var image1 = landsat.median().clip(region);   // median is more robust than mean to outliers

That is why this script uses median() instead of mean(). We do the same before classifying the NDVI collection: var input = ndvi.median();

Step 7a · script section 4

K-Means: grouping pixels by similarity

Every pixel now has an NDVI value. We want to sort them into groups like "very green", "medium", "low", without choosing the boundaries ourselves. K-Means learns them from the data. This is called unsupervised classification, because we never show the computer an example saying "this pixel is forest".

The algorithm is simple and repeats two steps:

1. Assign: each pixel joins its nearest centre.
2. Update: each centre moves to the average of its group.
It stops when the centres stop moving.

Try it: 80 pixels, 4 clusters (the script uses 6 clusters and 5,000 pixels)

An important trap: K-Means numbers its clusters arbitrarily. "Cluster 0" does not mean the lowest NDVI; a different group can be 0 on every run. Press "New random start" a few times above and watch the colour order get shuffled. Linking a light-to-dark green palette to those arbitrary numbers can make the map hard to read.

This script computes the mean NDVI of each cluster, sorts them from lowest to highest, then renumbers them (remap). Now 0 really is the lowest NDVI and 5 the highest.

var training  = input.sample({region: forests.geometry(), scale: 30, numPixels: 5000, seed: 42});
var clusterer = ee.Clusterer.wekaKMeans(6).train(training);   // learn from 5,000 samples
var clustered = input.cluster(clusterer);                     // apply to every pixel
// ... mean NDVI of each cluster → sort → remap
var ranked = clustered.remap(order, ee.List.sequence(0, 5));

seed: 42 fixes the random draw: the same 5,000 pixels are picked every time you run the script, so the result does not change.

Step 7b · script section 5

Charts: how did NDVI change during the summers?

A chart needs one value per month. So we build two nested loops: 12 years × 3 summer months (June, July, August) = 36 boxes. Each box holds the mean of the clear images taken that month.

Reducers: turning thousands of pixels into one number

Each monthly image covers our region with thousands of pixels. For one point on the chart we have to summarise them. The tool that does this is called a reducer:

ui.Chart.image.series({
  imageCollection: summerNDVI,   // 36 (or fewer) monthly images
  region: region,
  reducer: ee.Reducer.mean(),    // regional mean for each month
  scale: 100,                    // computation resolution (m): larger is faster but coarser
  xProperty: 'system:time_start' // x axis = date
});

seriesByRegion does the same for each of the three counties and draws one line per county. seriesProperty: 'NAME' takes each line's label from the county name.

Legends

The legend code is pure interface work: it opens a panel and adds one row per colour, made of a coloured box and a label. Both legends are built with a single makeLegend(title, colours, names) function.

Step 8 · script section 7

Export and QGIS: getting the results onto your computer

Everything you see in GEE lives on the server. To get it as a file we use Export. An export creates a "task", but it does not start by itself:

  1. Run the script. Orange tasks appear in the Tasks tab on the right.
  2. Click Run on each task. The whole area is computed now; this can take a few minutes.
  3. Google Drive → your export folder. NDVI and classes arrive as GeoTIFF, counties as a Shapefile.
  4. Load them into QGIS. Layer → Add Layer → Add Raster Layer / Add Vector Layer.
  5. Clip. Processing Toolbox → Clip raster by mask layer, with forests as the mask.
  6. Style. Right-click the layer → Properties → Symbology → Singleband pseudocolor, green colour ramp.
Export tips: (1) Pass a single image — this script exports input (the median NDVI), not the whole collection. (2) In QGIS use Properties for symbology (not "Processing"). (3) When clipping, avoid 0 as NoData — it is a valid NDVI; use something like −9999 instead.
Common tip: Permission denied to create object in folder. GEE finds the Drive folder by its name. If a read-only folder shared with you has the same name, GEE tries to write there and fails. Pick a unique folder name.

Glossary

Pixel
The smallest square of an image. 30 × 30 m for Landsat.
Band
A layer that measures one kind of light (red, NIR…).
Reflectance
The share of incoming light a surface sends back (0–1).
DN
The raw integer stored in the file; converted to reflectance with the scale factor.
Image
A single image (it can hold several bands).
ImageCollection
A stack of images, usually the same place on different dates.
Feature / FeatureCollection
A shape plus an attribute row / a table of them (a vector layer).
filterDate, filterBounds
Filter a stack by date and by location.
map()
Applies a function to every element of a collection.
Mask
A 1/0 layer that says which pixels to use.
Bit
One digit of a binary number; in QA_PIXEL each bit is a yes/no answer.
NDVI
(NIR − Red) / (NIR + Red); a vegetation index between −1 and +1.
Composite
A single image that summarises values over time, pixel by pixel.
Reducer
An operation that turns many values into one: mean, median, max…
K-Means
An unsupervised method that splits pixels into k groups by similarity.
scale
The pixel size (in metres) at which a computation runs.
Export
A task that writes results to Drive as files.
