Vue d'ensemble : que fait-on ?

La question est simple : quel est l'état de la végétation dans trois comtés forestiers du nord-est des États-Unis, et comment a-t-il évolué pendant les étés de 2014 à 2025 ?

Pour y répondre, on prend 12 ans d'images Landsat 8, on retire les nuages, on calcule un « score de verdure » (le NDVI) pour chaque pixel, puis on transforme ces scores en cartes, en classes et en graphiques. Le script suit ces huit étapes :

Comment fonctionne GEE ? Votre code est une recette. Vous l'envoyez aux serveurs de Google : ils détiennent les ingrédients (des pétaoctets d'images) et font la cuisine. Ils ne cuisinent d'ailleurs que la partie affichée à l'écran. C'est pourquoi 12 ans de données s'affichent en quelques secondes, alors qu'un Export calcule toute la zone et peut prendre plusieurs minutes.
Notion de base

Une image satellite est en réalité un tableau de nombres

Pensez à une photo de téléphone : elle est faite de petits carrés, les pixels. Avec Landsat, chaque pixel couvre 30 × 30 mètres au sol ; un terrain de football fait environ 8 pixels.

La différence : un téléphone mesure 3 couleurs par pixel (rouge, vert, bleu). Landsat mesure aussi des lumières que nos yeux ne voient pas. Chaque type de lumière forme une couche à part, appelée bande. Une image est une pile de bandes.

Les bandes utilisées dans l'atelier :

SR signifie « Surface Reflectance » (réflectance de surface) : des valeurs corrigées des effets de l'atmosphère, proches de la réflectance réelle du sol.

Étape 2 · section 2 du script

ImageCollection : une pile d'images prises dans le temps

Depuis 2013, Landsat 8 survole chaque point de la Terre tous les 16 jours et prend une image. Chaque passage produit une image couvrant une bande de terrain (une « scène » d'environ 185 × 180 km). Toutes se trouvent dans la collection LANDSAT/LC08/C02/T1_L2 : des centaines de milliers d'images dans le monde.

Deux filtres la réduisent à une petite pile exploitable :

var landsat = ee.ImageCollection('LANDSAT/LC08/C02/T1_L2')
  .filterDate('2014-01-01', '2026-01-01')  // date de fin exclue → jusqu'à fin 2025
  .filterBounds(forests)                   // seulement les scènes qui touchent nos comtés
  .map(prepL8);                            // appliquer la fonction de préparation à chacune

print("Nombre d'images Landsat", landsat.size());
Dans cette version : la date de fin est '2026-01-01' pour inclure tout 2025 (GEE exclut la date de fin). Le composite est calculé sur la collection filtrée spatialement, pas sur une pile mondiale non filtrée.
Notion

.map() : appliquer la même opération à chaque image

La pile contient des centaines d'images, et on veut faire la même chose à chacune : retirer les nuages, mettre les valeurs à l'échelle, calculer le NDVI. On écrit donc l'opération une seule fois sous forme de fonction, puis on l'applique à chaque image avec .map().

Analogie : une macro de retouche photo qui applique le même filtre à toutes les photos d'un album. La fonction décrit quoi faire avec une photo ; .map() applique cette recette à tout l'album. 400 images en entrée, 400 images en sortie.
Étape 3 · fonction prepL8

Masque nuages : lire la bande QA_PIXEL

Un nuage cache la forêt qui se trouve dessous. Le NDVI d'un pixel nuageux mesure le nuage, pas la forêt : il faut donc écarter ces pixels.

Landsat attribue à chaque pixel un indicateur de qualité : la bande QA_PIXEL. C'est un seul nombre, mais il regroupe en fait 16 réponses oui/non. Écrit en binaire, chaque chiffre (bit) répond à une question :

BitQuestionBitQuestion
0Pas de donnée ?5Neige ?
1Bord de nuage ?6Dégagé ?
2Cirrus ?7Eau ?
3Nuage ?8–15Niveaux de confiance (deux bits chacun)
4Ombre de nuage ?

À vous : décoder une valeur de QA_PIXEL

Test nuage · valeur AND 8
0
Test ombre · valeur AND 16
0

1 << 3 signifie « décaler 1 de trois positions vers la gauche » : 1000 en binaire, soit 8. 1 << 4 = 16. bitwiseAnd(8) ne regarde que le bit 3 : si le résultat vaut 0, le bit est éteint et le pixel n'est pas un nuage.

function prepL8(image) {
  var qa = image.select('QA_PIXEL');
  var mask = qa.bitwiseAnd(1 << 3).eq(0)       // bit nuage éteint ET
    .and(qa.bitwiseAnd(1 << 4).eq(0));          // bit ombre éteint → 1 (garder), sinon 0
  var sr = image.select('SR_B.').multiply(0.0000275).add(-0.2);  // mise à l'échelle (voir plus bas)
  return image.addBands(sr, null, true).updateMask(mask);
}

updateMask considère comme « absents » les pixels où le masque vaut 0. Ils ne sont pas supprimés, mais aucun calcul ultérieur ne les utilise, et ils apparaissent transparents sur la carte.

Étape 5 · section 3 du script

NDVI : un « score de santé » de la végétation

Une feuille en bonne santé fait deux choses à la fois :

Elle absorbe la lumière rouge. La chlorophylle utilise le rouge pour la photosynthèse, la feuille en renvoie donc très peu.
Elle réfléchit fortement le proche infrarouge (PIR). La structure interne des cellules de la feuille renvoie le PIR comme un miroir. Nous ne le voyons pas, le satellite si.

Le sol et l'eau n'ont pas ce comportement. Plus l'écart entre les deux est grand, plus la végétation est dense et saine.

Le NDVI résume cet écart en un seul nombre :

NDVI = (PIR − Rouge) / (PIR + Rouge)

Pourquoi diviser ? Une même forêt paraît plus claire sur un versant ensoleillé et plus sombre à l'ombre, mais le rapport reste le même. Le résultat est toujours compris entre −1 et +1.

function addNDVI(image) {
  // normalizedDifference(['A','B']) = (A − B) / (A + B)
  var nd = image.normalizedDifference(['SR_B5', 'SR_B4']).rename('NDVI');
  return image.addBands(nd).select('NDVI');
}
var ndvi = landsat.map(addNDVI);   // une image NDVI par image de la pile

normalizedDifference est le raccourci intégré de nir.subtract(red).divide(nir.add(red)). Le résultat est identique.

Étape 4 · le point méthodologique le plus important

Facteur d'échelle : des nombres bruts à la vraie réflectance

Plus haut, on a utilisé des réflectances comme 0,04 ou 0,45. Les fichiers Landsat ne les stockent pas ainsi. Pour gagner de la place, elles sont converties en entiers : au lieu de 0,45, le fichier contient 23 636. On parle de DN (Digital Numbers, valeurs brutes).

La formule de l'USGS pour revenir à la réflectance :

réflectance = DN × 0,0000275 − 0,2

Si l'on saute cette conversion et calcule le NDVI sur les valeurs brutes, on pourrait penser que « c'est un rapport, donc ça ne change rien » — mais le décalage de −0,2 fausse le rapport. La valeur calculée sur les DN vaut en réalité :

NDVI non mis à l'échelle = (PIR − Rouge) / (PIR + Rouge + 0,4)

Le 0,4 ajouté au dénominateur rend tous les NDVI trop faibles et les resserre. La comparaison ci-dessous se met à jour quand vous déplacez les curseurs plus haut :

Étape 6

Composite : réduire 400 images à une seule

Pour afficher une seule image sur la carte, ou pour découper une zone (clip), il faut une image unique. On l'obtient en résumant les valeurs de chaque pixel dans le temps en une seule valeur. C'est ce qu'on appelle un composite.

Imaginons qu'on ait mesuré un pixel à 9 dates. Le masque a retiré la plupart des nuages, mais à deux dates un bord de nuage ou de la brume est passé à travers :

var image1 = landsat.median().clip(region);   // median plus robuste que mean face aux extrêmes

C'est pourquoi ce script utilise median() plutôt que mean(). On fait de même avant de classifier la collection NDVI : var input = ndvi.median();

Étape 7a · section 4 du script

K-Means : regrouper les pixels par ressemblance

Chaque pixel a maintenant une valeur de NDVI. On veut les répartir en groupes du type « très vert », « moyen », « faible », sans fixer nous-mêmes les limites. K-Means les apprend à partir des données. On parle de classification non supervisée, car on ne montre jamais d'exemple à l'ordinateur du genre « ce pixel est une forêt ».

L'algorithme est simple et répète deux étapes :

1. Affecter : chaque pixel rejoint le centre le plus proche.
2. Mettre à jour : chaque centre se déplace à la moyenne de son groupe.
Il s'arrête quand les centres ne bougent plus.

À vous : 80 pixels, 4 classes (le script utilise 6 classes et 5 000 pixels)

Un piège important : K-Means numérote ses classes au hasard. « Classe 0 » ne veut pas dire NDVI le plus faible ; un groupe différent peut être 0 à chaque exécution. Cliquez plusieurs fois sur « Nouveau départ aléatoire » et regardez l'ordre des couleurs se mélanger. Associer une palette du vert clair au vert foncé à ces numéros arbitraires rend la carte difficile à lire.

Ce script calcule le NDVI moyen de chaque classe, les trie du plus faible au plus élevé, puis les renumérote (remap). Désormais, 0 correspond vraiment au NDVI le plus faible et 5 au plus élevé.

var training  = input.sample({region: forests.geometry(), scale: 30, numPixels: 5000, seed: 42});
var clusterer = ee.Clusterer.wekaKMeans(6).train(training);   // apprendre sur 5 000 échantillons
var clustered = input.cluster(clusterer);                     // appliquer à tous les pixels
// ... NDVI moyen de chaque classe → tri → remap
var ranked = clustered.remap(order, ee.List.sequence(0, 5));

seed: 42 fige le tirage aléatoire : les mêmes 5 000 pixels sont choisis à chaque exécution, et le résultat ne change pas.

Étape 7b · section 5 du script

Graphiques : comment le NDVI a-t-il évolué l'été ?

Un graphique a besoin d'une valeur par mois. On construit donc deux boucles imbriquées : 12 ans × 3 mois d'été (juin, juillet, août) = 36 cases. Chaque case contient la moyenne des images dégagées prises ce mois-là.

Réducteurs : transformer des milliers de pixels en un nombre

Chaque image mensuelle couvre notre zone avec des milliers de pixels. Pour un point du graphique, il faut les résumer. L'outil qui fait cela s'appelle un réducteur (reducer) :

ui.Chart.image.series({
  imageCollection: summerNDVI,   // 36 images mensuelles (ou moins)
  region: region,
  reducer: ee.Reducer.mean(),    // moyenne de la zone pour chaque mois
  scale: 100,                    // résolution de calcul (m) : plus grand = plus rapide mais plus grossier
  xProperty: 'system:time_start' // axe x = date
});

seriesByRegion fait la même chose pour chacun des trois comtés et trace une courbe par comté. seriesProperty: 'NAME' donne à chaque courbe le nom du comté.

Étape 8 · section 7 du script

Export et QGIS : récupérer les résultats sur son ordinateur

Tout ce que vous voyez dans GEE vit sur le serveur. Pour l'obtenir sous forme de fichier, on utilise Export. Un export crée une « tâche », qui ne démarre pas toute seule :

  1. Exécuter le script. Des tâches orange apparaissent dans l'onglet Tasks à droite.
  2. Cliquer sur Run pour chaque tâche. Toute la zone est calculée à ce moment-là ; cela peut prendre quelques minutes.
  3. Google Drive → dossier d'export. Le NDVI et les classes arrivent en GeoTIFF, les comtés en Shapefile.
  4. Charger dans QGIS. Couche → Ajouter une couche → raster / vecteur.
  5. Découper. Boîte à outils de traitements → Découper un raster selon une couche de masque, avec forests comme masque.
  6. Symboliser. Clic droit sur la couche → Propriétés → Symbologie → Pseudo-couleur à bande unique, rampe de verts.
Astuces d'export : (1) Passer une seule image — ce script exporte input (le NDVI médian), pas toute la collection. (2) Dans QGIS, utiliser Properties pour la symbologie (pas « Processing »). (3) Au découpage, éviter 0 comme NoData — c'est un NDVI valide ; utiliser par exemple −9999.
Astuce fréquente : Permission denied to create object in folder. GEE trouve le dossier Drive par son nom. Si un dossier partagé en lecture seule porte le même nom, GEE essaie d'y écrire et échoue. Choisissez un nom de dossier unique.

Glossaire

Pixel
Le plus petit carré d'une image. 30 × 30 m pour Landsat.
Bande
Une couche qui mesure un type de lumière (rouge, PIR…).
Réflectance
La part de la lumière reçue qu'une surface renvoie (0–1).
DN
L'entier brut stocké dans le fichier ; converti en réflectance par le facteur d'échelle.
Image
Une image unique (elle peut contenir plusieurs bandes).
ImageCollection
Une pile d'images, en général le même lieu à différentes dates.
Feature / FeatureCollection
Une forme et sa ligne d'attributs / une table de celles-ci (une couche vecteur).
filterDate, filterBounds
Filtrent une pile par date et par emprise.
map()
Applique une fonction à chaque élément d'une collection.
Masque
Une couche 1/0 qui indique quels pixels utiliser.
Bit
Un chiffre d'un nombre binaire ; dans QA_PIXEL, chaque bit est une réponse oui/non.
NDVI
(PIR − Rouge) / (PIR + Rouge) ; indice de végétation compris entre −1 et +1.
Composite
Une image unique qui résume les valeurs dans le temps, pixel par pixel.
Réducteur
Une opération qui transforme plusieurs valeurs en une : moyenne, médiane, maximum…
K-Means
Méthode non supervisée qui répartit les pixels en k groupes selon leur ressemblance.
scale
La taille de pixel (en mètres) à laquelle un calcul est effectué.
Export
Une tâche qui écrit les résultats dans Drive sous forme de fichiers.
